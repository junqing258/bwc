# 建筑模型解析、预览与算量：AI 工作流工具调研

调研日期：2026-10-27。面向筑材智算的产品改造决策。

本次阅读了官方产品页、帮助文档、公开仓库 README、许可文件及仓库状态，并结合原项目已有调研判断适配性。没有注册试用、购买订阅、上传工程文件，也没有实测各产品的解析完整性、准确率、大型模型性能与中国计量规则。下文“已提供”表示有公开产品或技术文档证据；产品效果与推荐顺序仍需样本验证。

## 1. 核心结论

**已有相当接近“AI Skill + 模型解析 + 预览 + 结果”的工具，建议先试用和复用，再决定自建范围。**

1. **Speckle Intelligence 最接近“模型数据 + 三维交互 + 可复用 Skill”这一产品形态。** 它有官方 Skills、模型聊天、数量与自带价格表结合的工作流。需要先把模型发布或导入 Speckle；其 AI 查询不等于编辑原建模文件。
2. **Sparkel 最接近“通过 AI 调用现成算量服务，并直接显示交互预览”。** 官方 MCP 提供上传、表格、Autoshapes、导出及交互式二维/三维预览；BIM 功能需要 Pro。
3. **本地能力已有可复用工具。** IfcOpenShell 官方 IfcMCP 已提供 IFC 加载、查询、检查、编辑、算量和渲染工具；但渲染返回图片，完整交互式查看器仍需另接。
4. **桌面工作流入口已有 OpenWork、Cherry Studio、Claude Cowork、AnythingLLM。** 它们适合承载任务、技能和工具，建筑格式支持依赖外接工具。不同客户端的 MCP Apps 支持不能想当然。
5. **Dify、n8n、Langflow 是后台编排候选。** 它们能管理模型调用、条件、工具、流程和部分人工介入；CAD/BIM 的几何解析、三维交互和计量规则依然需要专门能力。
6. **国内已有接近业务结果的产品。** MAXI 的公开方案包含自然语言、CAD 解析、算量和图模联动；思沃克 AMT 聚焦 DXF 工程量提取。应要求真实样本演示，不能仅凭宣传确认可交付范围。

上述判断的直接依据详见各产品条目；未找到足够证据证明其中任何单一产品能开箱覆盖“任意 DWG/IFC/GLB/FBX/MAX + 大型复杂项目 + 中国项目计量规则 + 本地部署 + 小白操作”全部要求。这是本次检索范围内的证据结论，不是对全市场的不存在证明。

## 2. 四种不同的工具，不宜混在一起比较

| 层次 | 用户得到什么 | 代表 | 对筑材智算的意义 |
| --- | --- | --- | --- |
| 建筑专用成品 | 上传/发布模型、查看、查询、数量或报告 | Sparkel、Speckle、Kreo | 可以直接试用；优先验证是否已满足任务 |
| 建模软件内 AI | 直接操作当前专业软件的模型和视图 | Revit MCP、Archicad MCP、Argus、Glyph | 面向已有专业软件的团队，复用其模型环境 |
| 通用桌面 Agent | 描述目标，Agent 使用文件、Skill、MCP | OpenWork、Cherry Studio、Cowork、AnythingLLM | 可作为低成本原型入口，配合领域工具 |
| 编排平台和开发组件 | 工作流、API、领域工具、查看器 | Dify、n8n、Langflow、Coze、IfcMCP、That Open | 用来开发和集成，仍需产品化 |

本报告检视 20 个产品或组件：Speckle、Sparkel、Kreo、Togal、Beam AI、MAXI、AMT、Revit MCP、Archicad MCP、Argus、Glyph、OpenWork、Cherry Studio、Cowork、AnythingLLM、Dify、n8n、Langflow、Coze/Coze Studio、Flowise；另评估 IfcMCP、That Open 和 MCP Apps 作为技术组件。后者不计作现成业务应用。

## 3. 最值得先试的两项建筑专用产品

### 3.1 Speckle Intelligence + Skills + Automate

**匹配判断：最值得参考整体产品形态，并验证能否替代部分自建工作。**

官方提供两种 AI 入口：项目 Chat 与主三维查看器里的聊天入口。AI 读取已发布模型的数据，可以回答项目和构件问题，生成图表，并改变查看器中的显示。官方强调按需查询紧凑数据，而非将完整模型放入大模型上下文。[Intelligence 文档](https://docs.speckle.systems/analytics/intelligence.md)

其 Skills 是工作区内的可复用指令，可保存对话为技能、由 AI 起草技能、绑定资料并共享。技能可以在项目 Chat 和三维视图里用 `/skill-name` 调用；文档说明它作用于下一条消息，工作区技能不会自动在每次对话中执行。[Skills 文档](https://docs.speckle.systems/analytics/intelligence-skills)

官方另有明确的材料数量与估价流程：绑定用户自己的价格表，读取已发布模型数量，按类别、楼层等分组，匹配价格；缺少价格的项单列。它依赖已有数据与价格口径，不能据此确认已实现中国工程计量扣减规则。[数量与价格工作流](https://docs.speckle.systems/workflows/take-off-quantities)

Automate 可在模型新版本发布后运行自定义代码，适合质量检查、转换与报告。官方将其列为 Enterprise 能力；当前文档对托管企业工作区和企业服务器均有描述，具体部署与套餐需确认。[Automate 文档](https://docs.speckle.systems/developers/automate/introduction)

**部署与费用：**有免费 Explore 入口和定制付费方案；企业自托管需要商业许可及企业镜像，不应把公开服务器源码等同于完整商业 AI 平台。文档说明自托管 Enterprise Server 可配置组织 AI 提供商。[价格](https://speckle.systems/pricing/)、[企业部署](https://docs.speckle.systems/developers/server/deployment/enterprise-license)

**对本项目的限制：**需要验证原文件到 Speckle 数据的保真程度、所需数量属性、真实项目容量、人工修正方法与历史结果冻结方式。官方数量工作流的报告可保持与绑定版本联动，筑材智算若需合同或询价快照，应另外验证固定结果的交付方式。

### 3.2 Sparkel + 官方 MCP

**匹配判断：最适合先验证“AI 发起任务 + 专业工具执行 + 交互预览”。**

官方帮助明确列出 MCP 能力：浏览项目、表格、模型；上传 PDF 和 Pro BIM 文件；校准图纸；运行 Autoshapes；更新数据；导出结果。`sparkel_render` 可以在支持 MCP Apps 的客户端展示交互式 3D 或图纸预览。二维图纸与三维 BIM 需要分别调用预览。[官方 MCP 使用说明](https://intercom.help/sparkel-2439628b406a/en/articles/16460144-using-sparkel-from-an-ai-assistant-mcp)

这是一条已有文档的成品集成路径：兼容 AI 客户端 → Sparkel MCP → 上传/识别/数据处理 → 预览/导出。既可在原应用使用，也可由外部 Agent 调用。[MCP 产品入口](https://www.sparkel.ai/mcp)

**调研日公开价格：**Free 为 €0，含 PDF 基础能力；Standard 为 €39/月/公司；Pro 为 €129/月/公司或 €1,238/年，含 IFC/Revit 上传、API 与 BIM 工作流。Pro 每月含 800 credits，BIM 上传列示为每次 15 credits，Copilot 另按使用量计费。以官网结账与合同为准，不使用第三方页面的“按用户”口径。[价格页](https://www.sparkel.ai/pricing)

**对本项目的限制：**本次没有确认私有化交付、完整中国计量规则或原生 DWG/MAX 支持；也没有验证大模型容量。MCP 支持需要客户端和服务器配套，普通 MCP 连接成功不代表能显示交互界面。

## 4. 能复用的本地解析与预览组件

### 4.1 IfcOpenShell 官方 IfcMCP

**匹配判断：IFC 主路径应优先评估，避免从零重写一套工具接口。**

官方工具包括 `ifc_load`、`ifc_summary`、`ifc_tree`、`ifc_select`、`ifc_info`、`ifc_materials`、`ifc_validate`、`ifc_clash`、`ifc_edit` 和 `ifc_quantify`。其中算量会写入模型数量集，保存接口也包含覆盖原路径的行为；正式业务应通过工作副本、修订和有限工具接口管理变更。[IfcMCP 文档](https://docs.ifcopenshell.org/ifcmcp.html)

`ifc_plot` 返回二维图像，`ifc_render` 返回离屏 PNG。因此它能让 AI 检视渲染结果，但没有直接证明提供用户可旋转、点选的交互预览。其会话内持有 IFC 模型，仍需实测大文件内存、取消与恢复。

IfcMCP 位于 IfcOpenShell 官方工具生态中，仓库列其许可为 LGPL-3.0-or-later；几何绑定和渲染依赖需按目标安装包验证。[官方仓库](https://github.com/IfcOpenShell/IfcOpenShell)

### 4.2 That Open Components / Fragments

**匹配判断：适合补齐浏览器交互预览，属于开发组件。**

That Open 提供开发 BIM 软件的开源库；Fragments 面向 BIM 数据和显示，项目采用 MIT 许可。它可以作为预览层候选；具体 IFC 导入、对象映射、显示质量及容量仍需集成验证。[官方开发文档](https://docs.thatopen.com/intro)、[Fragments 仓库](https://github.com/ThatOpen/engine_fragment)

建议将查看器封装成可定位、选择、高亮的工具界面，计量结果引用独立计算依据。无需因为使用该库就同时重写所有现有 Three.js 功能。

### 4.3 MCP Apps：把交互模型放进会话的标准能力

MCP Apps 是 MCP 的 UI 扩展，可以让工具返回在宿主中渲染的交互界面，官方用例包含 3D 模型、表单与可视化。模型需要的信息和 UI 所需数据可分别传递。宿主不支持时可以退回文本结果。[官方技术概述](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html)

**建议：**将自有预览器设计成可独立运行的网页，再按目标客户端接 MCP Apps。先验证模型访问、文件授权和选择结果回传；不要让首版必须依赖某客户端尚未交付的 UI 扩展。

## 5. 通用桌面 Agent：无需先自建整个应用入口

| 工具 | 已核对能力 | 适合用途 | 对模型预览的限制 |
| --- | --- | --- | --- |
| OpenWork | 桌面、本地文件、多模型、Skills、MCP、团队能力分享 | 本地 Skill 工作流原型；评估自有桌面产品底座 | 官方路线图仍将 MCP Apps 列为 Building；先配外部或内置浏览器预览 |
| Cherry Studio | Agent 工作区、文件工具、Skills、MCP、多模型 | 中文用户的任务入口候选 | 没有内置通用 BIM 引擎；MCP Apps 要按桌面版本实际验证 |
| Claude Cowork | 目标驱动任务、插件、Skills、连接器 | 快速验证工作方法和商业 MCP 服务 | 当前个人套餐新任务云端运行；非离线本地算量应用 |
| AnythingLLM | Desktop、Agent Flows、MCP 工具 | 文档与结构化工具辅助流程 | Desktop 文档明确仅支持 MCP Tools，不支持 Resources/Prompts/Sampling；不能默认获得 MCP Apps 预览 |

### OpenWork 的关键边界

官方 README 描述其基于 OpenCode，支持本地文件、多个模型提供商以及团队共享技能和 MCP。当前代码按目录区分：`ee/` 外为 MIT；组织控制平面 `ee/` 采用另一许可，生产使用有订阅及例外条件。不能把桌面核心的许可概括到整套组织平台。[官方 README 与许可说明](https://github.com/different-ai/openwork)

2026-10-27 官方路线图将桌面 Skills、连接、浏览器和文件列为 Ready；MCP Apps 和 Live artifacts 仍为 Building。[路线图](https://openworklabs.com/roadmap)

本次通过 GitHub API 核对仓库未归档且仍有更新；这只能证明维护状态，不能代替安装稳定性测试。“本地应用”也不等于资料不出网：采用云模型时，工具返回的字段、图像或会话内容仍可能发送给模型服务。

### Cherry Studio 的关键边界

官方文档明确区分：Skills 负责工作方法，MCP 连接外部系统，知识库提供资料，内置工具执行文件与搜索等操作。它适合把建筑领域工具包装成普通用户可调用的 Agent。[官方能力说明](https://cherryai.com/docs/en/advanced-basic/agent-workspace/tools-knowledge-skills-mcp/)

公开仓库为 AGPL-3.0，使用现成客户端和把源码改造成自有商业产品是不同决策，应按最终使用方式检查许可。[仓库](https://github.com/CherryHQ/cherry-studio)、[许可原文](https://github.com/CherryHQ/cherry-studio/blob/main/LICENSE)

### Claude Cowork 的近期变化

插件可以打包 Skills 和连接器等能力。[官方插件介绍](https://claude.com/resources/articles/cowork-plugins)

但 2026-10-06 起 Pro/Max 新任务改为云端执行；桌面仍能通过已连接文件夹访问本地文件。不能沿用早期资料将当前个人版描述为纯本地执行，也不能把本地连接器误认为云任务直接读取任意本机路径。[当前官方说明](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)

### AnythingLLM 的能力边界

Agent Flows 提供可视化流程来构建自定义 Agent 能力；这是另一种技能机制，不应未经验证就当作标准 `SKILL.md` 包的直接替代。[Agent Flows](https://docs.anythingllm.com/agent-flows/overview)

本次没有找到足够依据将其推荐为 BIM 交互预览入口，Desktop MCP 文档的 Tools-only 限制应在选型时保留。[Desktop MCP 文档](https://docs.anythingllm.com/mcp-compatibility/desktop)

## 6. 通用工作流平台：适合后台，领域能力仍需接入

| 平台 | 与本项目有关的已有机制 | 最适合的位置 | 本次判断 |
| --- | --- | --- | --- |
| Dify | Workflow/Chatflow、API/MCP 工具、分支循环、Human Input、自托管 | 自有任务界面后的 AI 编排 | 固定阶段与问题卡原型值得验证 |
| n8n | AI Agent、MCP、人工审阅、系统集成 | 文件事件、任务状态、报表和业务集成 | 适合外围编排，不承担几何内核 |
| Langflow | Python、自定义组件、可视化 Flow、MCP client/server、API | 几何工具与 AI 的开发验证 | Python 工具链团队可优先试 |
| Coze / Coze Studio | 智能体、可视化工作流、插件、API；云版支持 MCP 插件 | 国内云端原型或自部署候选 | 必须区分云产品与开源版本能力 |
| Flowise | 曾有 Agentflow、MCP、Human Input | 旧方案参考 | 官方仓库已归档，不作为新项目首选 |

### Dify

官方 Workflow Studio 支持将模型、工具、代码、条件和人工审阅组成流程，并发布为应用、API 或 MCP 工具。[产品文档](https://www.dify.ai/workflows)

Human Input 能暂停流程、收集表单输入和选择决定；当前文档也列出外部客户端经 Service API 驱动表单生命周期的方法。这与“缺厚度 → 用户补参 → 继续执行”相符，但不等于已有构件选择和三维联动。[Human Input 文档](https://docs.dify.ai/en/cloud/use-dify/nodes/human-input)

有 Docker Compose 自部署路径。其许可证基于 Apache 2.0 并附加多租户和前端标识条件，不能概括为无限制 Apache；要做多客户平台时需结合具体架构确认适用条件。[部署](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)、[许可原文](https://github.com/langgenius/dify/blob/main/LICENSE)

**本项目用法建议：**流程只传文件/项目引用、选择集、任务 ID、诊断和结果摘要。耗时解析交给外部 Worker，以任务提交和状态回传衔接，不把大型网格作为普通对话或节点变量流转。

### n8n

官方已有 AI 工具调用前的人工作业审阅机制，可在确定工具及参数后暂停、批准或拒绝。[人工审阅文档](https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools)

2026-10-06 更新的官方许可 FAQ 区分：内部人员创建工作流并向客户交付结果，与允许外部客户创建或配置工作流。后者即使使用自有界面、API、MCP 或 Agent，也可能需要商业许可。应引用当前说明，避免沿用旧文章对后台使用的一概判断。[当前许可 FAQ](https://support.n8n.io/article/can-i-use-your-license-for-my-use-case)

**本项目用法建议：**接收导入事件、调用解析服务、同步状态、整理结果和衔接报价系统；模型选择与高亮留在专门前端。

### Langflow

官方将其定义为 Python 可定制的开源 AI 应用框架，支持可视化编辑、自定义应用和 API。[官方介绍](https://docs.langflow.org/)

同时支持 MCP client/server，可把 Flow 暴露为工具。仓库采用 MIT 许可；本次核对未归档。[MCP 文档](https://docs.langflow.org/mcp-server)、[许可原文](https://github.com/langflow-ai/langflow/blob/main/LICENSE)

**本项目用法建议：**先用于 Python 几何工具与 Agent 的验证。复杂人工修订、重启恢复与多模型任务状态仍需实测，不能由“支持 Flow”推导出工程项目恢复能力已具备。

### Coze 与 Coze Studio

国内云产品支持基于 MCP 服务创建插件；当前文档要求插件 URL 为 HTTPS 域名，不能据此直接连接任意本机 stdio 工具。[云版 MCP 插件](https://docs.coze.cn/guides_create_a_plugin_based_on_mcp)

工作流 API 有明确请求及运行限制：请求整体 20MB；同步整体 10 分钟，异步可至 24 小时，异步使用受套餐条件约束。这些是平台流程限制，不是模型文件的可处理容量。[工作流 API](https://docs.coze.cn/developer_guides_workflow_run)

Coze Studio 另有开源仓库和 Docker 部署流程，采用 Apache-2.0。云版功能不能自动映射为该仓库同版本已实现功能，特别是插件、模型服务和发布渠道。[官方仓库](https://github.com/coze-dev/coze-studio)、[许可文件](https://github.com/coze-dev/coze-studio/blob/main/LICENSE-APACHE)

### Flowise：本次核对后的降级项

官方仓库显示 2026-08-13 归档，README 也明确标记已归档。现有资料里的 MCP 与人工介入功能仍可作为旧实现参考，但新项目若采用，需要自行维护或单独评估分支。[官方仓库](https://github.com/FlowiseAI/Flowise)、[维护方说明](https://github.com/FlowiseAI/Flowise/discussions/6727)

不将归档等同于立即无法运行，也不将静态官网仍在展示功能当作持续维护证据。

## 7. 专业建模软件内的 AI 工作流

| 产品 | 公开能力与状态 | 与本项目的关系 |
| --- | --- | --- |
| Revit Public MCP Server | Revit 2027 Technical Preview；查询模型、属性、选择/定位构件、打开/导出视图 | 已有 Revit 环境时优先验证，无需自建全部查看与查询功能 |
| Archicad MCP | Archicad 30 Beta；内置助手和公共 MCP，模型查询到批准的批量编辑；有订阅要求 | 是同类交互方式的官方实例，但仍依赖 Archicad |
| BIMLOGIQ Argus | Revit 内 Agent，目标规划、链式工具调用、保存可复用命令；官网列 Revit 2022–2026 | 最接近“在专业软件中把一次任务保存为工作流” |
| EvolveLAB Glyph | Revit 视图、图纸、标注、尺寸等任务及 Bundle；有 Copilot | 自动化工作包参考，主营出图而非独立模型解析算量 |

依据：[Revit 官方 MCP](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-GetStarted/files/GUID-80B05F4F-1642-46BD-ACED-699D3125AEB9.htm)、[Archicad 官方帮助](https://help.graphisoft.com/AC/30/INT/Topics/001_GettingHelp/AI_Assistant/ManageElementsMCP.html)、[Argus](https://bimlogiq.com/)、[Glyph](https://www.evolvelab.io/glyph/nGlyph%C3%82%C2%AE)。

这些产品能降低重复操作成本，但用户仍在专业建模软件和其数据体系中工作。对于只收到文件、希望快速得到材料结果的普通用户，仍需比较安装、授权和操作成本。

## 9. “Skill”名称相同，不代表可直接迁移

| 名称 | 实际角色 | 迁移时要检查 |
| --- | --- | --- |
| 标准 `SKILL.md` 技能包 | 指令、脚本、资料和资产的约定结构 | 客户端支持、脚本环境、文件权限、外部工具 |
| Speckle Intelligence Skills | 工作区指令与绑定知识，配合其模型查询/查看器 | 本次未验证标准技能目录的直接导入；不是通用任意代码运行时 |
| AnythingLLM Agent Skills / Flows | 工具能力及可视化流程机制 | 不应默认与 `SKILL.md` 格式等价 |
| 工作流节点图 | 明确的输入、状态、分支和执行路径 | 需要运行时和领域工具，不因可视化就能解析模型 |
| MCP 工具 | Agent 与外部能力之间的调用协议 | 连接类型、身份、对象引用、任务状态和结果语义 |
| MCP Apps | 工具提供交互 UI 的协议扩展 | 宿主能力、数据访问、选择回传与性能 |

标准技能结构依据：[Agent Skills 官方说明](https://agentskills.io/home)。其余差异依据前述各产品官方文档。

## 10. 对筑材智算的选型建议

### 路线 A：先验证现成产品是否已经够用

**优先试 Sparkel，再试 Speckle。** 前者检验 AI 到算量服务和交互预览的链路；后者检验模型数据、Skills、公司方法和报告复用。顺序是本项目试点建议，不是总体产品质量排名。

交付一个真实任务：上传/发布模型 → 用自然语言定位范围 → 展示问题 → 补充依据 → 输出可复核结果。若目标客户的文件与口径已经可用，可以先开发领域 Skill、模板与必要适配，而非重建通用平台。

需要确认的商业问题包括：允许的集成和交付方式、模型资料所在地、容量、API/MCP 套餐、计费、公司规则配置、结果导出与快照。不预设可白标转售或私有化。

### 路线 B：本地工作流原型

**OpenWork 或 Cherry Studio + 领域 Skill + IfcMCP + 独立交互预览器。**

这是一套建议组合，尚未在本次安装验证。Agent 负责任务，IfcMCP 提供 IFC 工具，查看器使用现有 Three.js 或评估 That Open。通过版本化对象引用让模型选择、问题卡与清单一致。

若首批实际来件主要是 DWG/DXF，则把 IfcMCP 替换为原项目已规划的 ACadSharp/ezdxf 适配器。必须明确：IfcMCP 解决 IFC，不提供 DWG/MAX 通用解析。

原型可先让 Agent 打开本机预览页。待目标宿主的 MCP Apps 支持和性能通过验证后，再把预览嵌进会话。面向小白分发仍需封装依赖和启动方式，不能把手配 MCP 留给最终用户。

### 路线 C：自有产品，保留现有前端

**现有 React/Three.js 界面 + 领域工具服务 + 按需选择 Dify 或 Langflow 做编排。**

Dify 优先验证引导式任务与问题卡；Langflow 优先验证 Python 工具链集成。n8n 按需要承担外围业务连接。没有必要在第一版同时引入三个编排平台。

用户界面继续收敛为任务、模型、待处理问题和结果；后台工作流画布留给开发或管理员。若后续发现项目状态与领域工具本身已能有效调度，可直接用较薄的 Agent 运行时，避免为了工作流可视化引入一整套平台。

**当前优先级建议：A → B → 依据验证结果决定 C 的范围。** 先确定现成能力的缺口，再开发真正需要差异化的中国计量规则、非规范文件处理和结果追溯。

## 11. 下一轮验证应怎样做

### 共用任务

1. 语义较完整的 IFC：按楼层选择楼板，区分已有数量与几何计算，生成材料汇总。
2. 有独立尺寸依据的 DWG/DXF：校准单位，提取目标轮廓，处理洞口并核对结果。
3. 合并网格或缺少厚度的展示模型：能否诚实保留缺项，通过选择和补充依据形成局部可用结果。
4. 真实复杂项目：包含多文件、多楼栋、实例、大坐标和未支持对象，检查首次预览、内存、失败范围与恢复。

### 统一记录

| 维度 | 记录内容 |
| --- | --- |
| 小白上手 | 从打开应用到看到正确预览的操作与时间，是否需要专业人员代配置 |
| 输入完整性 | 成功解析范围、未支持对象、外部引用、单位和坐标问题 |
| 交互预览 | 点选、高亮、隔离、结果回定位；区分截图和真正的交互视图 |
| AI 工作流 | 是否能连续推进、按组补资料、保留人工修改、恢复中断 |
| 数量可信度 | 按构件/单位核对漏项、重复、扣减、来源与计算方法 |
| 大模型与大项目 | 分别记录 AI 上下文大小、源文件/对象数、解析和显示内存，不混为一个指标 |
| 可追溯交付 | 文件/模型版本、采用参数、规则、缺项、报告和固定快照 |
| 总成本 | 平台费、AI 用量、解析资源、资料整理、人工复核和分发维护 |

进入开发前，至少获得一个现成产品和一个可复用本地工具的真实结果。这样才能判断筑材智算需要做的是领域工作流、几何适配、专用查看器，还是完整产品。
