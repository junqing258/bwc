# 筑材智算 Codex 插件改造规划

日期：2026-10-29。状态：P0 内核与 P1 插件/审阅代码已启动实施；具体完成项和验收缺口见 [Codex 插件实施记录](Codex插件实施记录.md)，本规划的 P2/P3/P4 未整体完成。

## 1. 产品目标与边界

将本项目改造为在 Codex 当前工作目录运行的建筑算量插件。用户在 Codex 中提出任务，插件读取本地 DWG、识别建筑构件、检查计量条件、生成可追溯工程量；需要核对时打开本地 Web 审阅器。

- Codex 工作目录就是项目根目录，不再另建应用项目、不提供项目列表或项目增删改。
- Codex 承担对话、任务理解、工具编排和进度说明。插件不再启动自己的 Codex App Server 或维护第二套聊天记录。
- 本地领域服务承担 DWG 解析、结构化数据、构件与规则、数值计算、版本和成果持久化。
- Web 用于查看图纸、核对识别、确认参数与范围、追查算量依据和审阅结果。关闭 Web 不应阻止解析、候选生成、已具备条件的算量及导出。
- 首期围绕二维建筑图的构件计数、长度、面积、净面积及参数体积；完整三维恢复、任意 DWG 编辑与保真另存不作为插件迁移验收前提。
- 最终建筑算量需要明确适用的专业、地区、规范及版本；未绑定规则时只能交付注明算法与范围的几何量，不能称为符合某规范的工程清单量。

| `skills/dwg-workflow/` | 解析、检查、选择、修改、算量工作流说明 | 重写为 Codex 插件入口，移除工作台消息与宿主前提 |

依据为当前代码与 `docs/二维构件识别.md`、`docs/解析诊断排查.md`。后者记录 `bwc-cad-4` 的附房样本已有 25,205 / 25,230 个模型实例具有规范表示，剩余 25 个缺口。该覆盖率不代表业务识别率、计量有效率或整图保真；旧 README 的图元缺口清单也不宜直接作为最新能力矩阵。

目前建筑识别仍缺自动墙线配对、楼层归属、门窗洞口关联、平立剖与详图去重及高度参数提取。这些是建筑算量能力建设，不能通过插件封装解决。

## 3. 目标架构

```text
Codex 当前任务 + dwg-workflow Skill
                  │ MCP / 本地 CLI
                  ▼
工作目录运行时 → 领域服务 → DWG Worker / 几何 Worker
                  │
                  ├─ 当前目录/.bwc/：状态、快照、证据与任务
                  ├─ 当前目录/成果目录：明细、汇总、依据报告
                  └─ 按需启动本地审阅服务 → 浏览器
                                            │
                                 核对事件写回同一领域服务
```

### 插件包与工作目录分离

插件安装目录存放只读程序、Skills、审阅静态资源和运行时入口；用户项目数据只写入工作目录。更新插件不覆盖工程资料。

建议包结构：

```text
plugin.json             插件身份与 OpenAI 设置
mcp.json                本地 MCP 入口配置
skills/dwg-workflow/     面向建筑算量的工作流说明
dist/                   编译后的服务、CLI、审阅资源
workers/                按平台分发的 Worker 与依赖清单
scripts/                环境检查与启动
```

官方当前推荐根目录 `plugin.json`、`mcp.json`、`skills/`；`.codex-plugin/plugin.json` 是兼容方式。实现阶段按目标 Codex 版本验证清单与本地 MCP 启动，不同时维护两套相互冲突的配置。首期交付本地安装插件，公共目录发布另行处理。参考：[OpenAI 官方插件打包文档](https://developers.openai.com/plugins/build/plugins)。

P1 必须交付首个平台的可安装发行包，包括编译后的服务端与 CLI、审阅静态资源、CAD/几何 Worker 及其运行依赖。程序和 Worker 路径相对插件安装位置解析，不依赖源码仓库、开发机 `.venv`、`tsx` 或仓库内的构建目录。P1 开始前固定目标 Codex 版本及安装方式，并列明 Node、.NET、Python 和几何库分别采用随包分发还是用户预装；预装项须给出支持版本、检测与安装说明，缺失时返回可操作的诊断，不在只读插件目录临时构建或安装依赖。

P0 开始前安排最小插件 spike：固定目标 Codex 版本、安装方式和清单格式，用 hello-world Skill 与本地 stdio MCP 实测安装、Skill 呈现、工具调用、进程退出与重连。另验证独立子进程能否在 MCP 会话退出后存活；不能假设 detached 启动即可绕过宿主的进程清理。记录版本、配置、日志和结论后，再投入 P1 发行包工程。若宿主不允许持久子进程，采用用户显式启动的本地运行时入口，并在发行说明中写明该前提。该 spike 是 P0 的前置技术验证，不等同于 P1 安装验收。

### 工作目录绑定

不能假定 MCP 进程的 cwd 一定是用户工程目录。Skill 应从 Codex 当前目录获得绝对路径，通过 `workspace_open(root)` 显式绑定；进程 cwd 只用作默认建议。返回稳定 workspaceId，后续调用校验归属；同一 MCP 服务面对多个工作目录时不得使用可被切换的全局“当前项目”变量。

建议工程布局：

```text
用户工程/
  任意已有目录/*.dwg       输入位置无需强制调整
  .bwc/
    workspace.json         工程标识、配置与 schema 版本
    workspace.sqlite       图纸、构件、规则、任务、审阅事件
    sources/               按指纹保存的不可变输入
    artifacts/             解析产物、索引、快照
    reviews/               审阅批次与证据
    cache/                 可重建的显示与中间数据
  outputs/bwc/             默认成果位置，可配置
```

首次执行写入任务时初始化 `.bwc/`。原 DWG 保持不变；按真实路径校验输入并处理符号链接。默认处理工程内文件，工程外文件通过显式导入复制为不可变来源。扫描跳过 `.bwc/`、输出目录和依赖目录。工程整体移动后，以相对路径与文件哈希恢复引用。

一个工作目录允许多张图纸和多个图纸版本。每张图独立管理快照、楼层/视图用途和当前版本；跨图成果通过一份输入清单冻结所有参与版本。当前单一 currentRevision 的模型需要扩展，不能靠反复导入覆盖当前图纸实现多图算量。

### P0 数据模型基线

P0 冻结并实现多图存储基础，P2 扩展多图业务编排，不再更换单图存储模型。`workspace.json` 首版明确 `schemaVersion: 1`、workspaceId、配置与数据库 schema 版本；SQLite 迁移另用递增版本管理，事务升级，遇到更新版本拒绝写入。

- `drawings`：逻辑图纸 ID、名称、专业、楼层/视图用途、currentRevisionId。
- `drawing_versions`：图纸 ID、不可变来源哈希、来源路径、原图/兼容副本关系。
- `geometry_snapshots`：图纸版本 ID、解析器版本、产物哈希与单位配置引用。
- `revisions`：图纸 ID、父修订 ID、快照 ID、业务参数版本；父修订和当前指针必须属于同一图纸。
- `input_manifests` 及成员：冻结一组 drawingId、revisionId、snapshotId，供跨图任务、覆盖审阅和成果引用。
- 构件、选择集、审阅和结果均显式绑定上述范围及版本；工作目录不设置全局 currentRevision。

具体 DDL、外键、唯一性与迁移脚本在 P0 设计评审时冻结。P0 可以只提供单图业务入口，但须以两张图验证存储及当前修订相互独立，并验证冻结输入清单不随当前指针变化。

### 运行与并发

MCP 与 CLI 共享领域层，CLI 作为诊断和批处理入口。审阅服务按需启动，仅监听本机并以短期令牌访问。浏览器不单独打开 SQLite；通过同一运行时提交审阅事件。

同一工作目录采用单写入运行时，MCP stdio 和 CLI 是客户端；运行时独立于会话进程。P0 按以下机制实现并验证：

1. 客户端执行 `ensureRuntime(root)`。先连接并验证已有实例；无可用实例时启动独立运行时进程，等待有超时的 ready 握手。多个客户端可以竞争启动，只有取得操作系统排他锁的进程能打开数据库和执行恢复，其余退出并重连胜出实例。
2. 首个平台使用操作系统 advisory lock（`flock` 或等价能力，由启动器/依赖明确实现），锁文件为 `.bwc/run/runtime.lock`。文件存在不代表持锁；不以 PID 文件的独占创建代替进程锁，也不删除正在使用的锁文件。系统在进程退出或崩溃后释放锁。
3. `.bwc/run/runtime.json` 原子写入 workspaceId、规范工程路径、PID、进程启动时间、随机 instanceId、协议版本、启动状态与心跳；同目录存日志和仅当前用户可读的连接凭据。使用回环地址动态端口作为 IPC，端点写入描述文件，避免工程路径过长导致 Unix socket 路径问题。令牌不进入模型输出或日志。
4. 客户端验证令牌握手、workspaceId、instanceId 和协议版本。PID 与启动时间用于排查 PID 复用，心跳用于判断疑似无响应，均不能单独作为抢锁依据。连接失败后重新尝试启动，仍必须取得系统锁才能接管；锁尚被持有时返回实例信息、日志位置和诊断/停止命令，不自动杀进程。
5. 崩溃后，新实例取得锁，再替换陈旧描述文件和凭据，检查 SQLite 与任务状态，仅将旧实例拥有的未完成任务标为 interrupted；按 operationId 和已提交记录对账，不盲目重跑。描述文件未落盘时崩溃也由系统锁释放恢复。
6. MCP 会话退出只断开客户端。运行时在没有客户端、运行任务或审阅连接后按配置空闲退出；显式停止先停止接单、处理任务并关闭数据库，再释放锁。清理描述文件前检查 instanceId，避免误删新实例状态。工作目录移动后的旧进程停止、新位置重开，不热迁移运行中的数据库。

保留基础版本比较、operationId 幂等、任务持久化与重启后对账。P0 故障验证至少覆盖同时启动、PID 复用/陈旧描述文件、握手前崩溃、任务中崩溃、MCP 退出后任务继续以及锁持有但服务无响应。先验证运行时单例，再开放多会话；避免每个 MCP 进程启动时把其他进程正在执行的任务判为 interrupted。

## 4. 端到端使用流程

1. 用户在 Codex 中要求：“识别当前目录建筑图，统计二层柱、门窗和楼板工程量。”
2. 插件绑定工作目录、发现 DWG、读取文件指纹并输出解析能力、外部依赖与缺失内容摘要。
3. 登记图纸用途、楼层、版本和单位；不能确定的项目列为待核实，不按文件名或标注数字直接定值。
4. 规则与 AI 协作识别候选，来源必须引用实际图元、块路径与快照；补充分类理由、缺失参数和可能重复项。
5. Codex 输出需要核对的条目及范围覆盖缺口。仅在目标宿主提供且已验证可信用户确认来源时，用户可在 Codex 明确确认结构化范围与参数；否则首期正式确认走 Web 批量核对。可用的确认入口写入同一审阅记录，并遵循下述可信人工确认约束。范围覆盖审阅独立于候选确认，包含尚未纳入候选的来源和解析缺口。
6. 通过检查的已确认构件按冻结范围与规则版本计算。缺少参数的项列为未计算，保留已知小计与完整性状态。
7. Codex 返回分类汇总、范围、未决项和成果路径；Web 可从结果行定位原图与计算依据。

不强制每个工具调用都人工批准。识别、诊断与试算可连续执行；首次出现无法推导的单位、业务参数或构件确认时，集中列出待核对项。将来允许的自动确认规则须单独定义并实测，首期不让模型自行将建议升级为人工确认。

## 5. 工具契约与审阅闭环

以下为建议工具名，现有工具可在适配层复用，避免一次性改名所有内部接口。

| 工具组 | 建议接口 | 核心约束 |
| --- | --- | --- |
| 工程 | `workspace_open/status` | 当前目录绑定，无项目创建、切换 UI |
| 输入 | `drawing_discover/import/list` | 本地路径导入、哈希去重、明确图纸与版本 |
| 解析 | `dwg_summary/diagnostics/query/get/reparse` | 分页、筛选，返回源引用与覆盖状态 |
| 识别 | `component_recognize/suggest/list` | 生成候选，禁止虚构几何和缺失尺寸 |
| 审阅 | `review_prepare/status`、人工提交入口 | 批次冻结对象版本；确认、驳回、修正、排除可追溯 |
| 覆盖 | `scope_coverage_prepare/status`、人工提交入口 | 冻结图纸版本及目标范围；记录未归属来源、排除理由、解析缺口与覆盖审阅结论 |
| 资料策略 | `data_policy_get`、人工设置入口 | 工程级策略版本化；默认摘要；扩大几何发送范围须可信人工授权 |
| 参数 | `measurement_profile_get/propose` | 单位、层高、厚度、扣减依据及来源 |
| 检查与计算 | `takeoff_check/run/get` | 图纸快照、构件版本、规则版本、输入范围固定 |
| 长任务 | `job_get/cancel` | 有阶段、错误与重启状态，避免长时间阻塞调用 |
| 交付 | `result_export`、`viewer_open` | 明细与依据报告；审阅链接绑定快照/对象/结果 |

当前写入 intent 依赖工作台消息，不能简单去掉校验。新增可审计的人工意图适配层：Web 核对事件可直接形成凭据；Codex 对话确认必须绑定已准备的审阅批次及其内容指纹，结合宿主可提供的用户确认能力验证。若目标宿主无法提供可信确认来源，则正式“人工确认”仍走 Web，Codex 可以继续识别和试算。不得只相信模型提交的 `userConfirmed: true`。

MCP 返回任务摘要和有限明细，完整几何与逐项报告留在本地，通过分页或引用获取；分页、引用解引用仍受资料发送策略约束。本地文件可读不等于自动上传全部几何。

现有资料过滤与发送审计位于 `apps/server/main.ts` 的 `/api/mcp` 链路，策略设置位于 `/api/policy`。P0 将其抽成共享的模型输出边界层，所有面向模型的 MCP 响应及 CLI 输出统一执行，覆盖同步结果、分页、引用读取、任务轮询与错误详情；本地审阅和成果文件使用独立的本地访问通道。CLI 默认采用模型安全输出，本地产物不得因引用读取而绕过过滤。删除原宿主链路前必须验证新边界层已接管过滤和审计。

资料策略保存在工作目录并带版本，默认 `summary`，详细几何仅在可信人工授权的图纸/范围内返回。Web 提供保留的工程资料发送设置；CLI 可由用户直接设置，Codex 对话设置遵循上述可信确认适配，无法验证来源时走 Web。模型不得通过普通工具参数自行扩大授权。策略更新记录前后值、范围、来源和时间；每次模型输出记录工具、策略版本、图纸快照、实际数据类别及过滤情况，不将被过滤的几何复制进审计。该边界约束插件提供的输出；Skill 同时要求不得用 shell 或直接读取本地产物绕过策略，不将其表述为对宿主全部文件访问的强制隔离。

## 6. 建筑识别与计量能力建设

识别链路分为：DWG 记录提取 → 坐标/单位规范化 → 图纸视图与楼层范围 → 几何组装 → 建筑构件候选 → 人工核对 → 计量规则。AI 用于语义解释和提出候选；边界、长度、面积和体积由 Worker 计算。

| 优先级 | 能力 | 可交付边界 |
| --- | --- | --- |
| 首批 | 柱、楼板、门窗 | 闭合边界/块实例候选；计数、净面积、人工参数体积；楼层和洞口关系显式确认 |
| 第二批 | 墙 | 双线配对、转角与交接、厚度、中心线、门窗洞口关联；先通过有参考答案的样本再交付 |
| 后续 | 梁、楼梯、复杂构件 | 平剖详图关联、高度依据、跨视图重复与规则处理 |

楼板厚度、柱高、墙高等必须记录数值、单位、来源与适用范围。文字/尺寸可提供参数证据，覆盖文字不能替代几何测量。长度、面积、参数体积与按规范扣减后的量分别表达，保留公式、规则 ID 和扣减明细。

构件的 canonical identity 应表达楼层与实际构件身份，再关联不同视图来源；跨视图匹配不确定时提交重复候选，不静默合并。HATCH、边界和块可能描述同一构件，必须检测同源及语义重复。

完整性至少分别记录：文件解析覆盖、目标范围识别覆盖、构件审阅状态、参数齐备性、规则检查与结果时效。计算项齐备与目标范围完成分别保存、展示；已选构件全部算出只能说明该选择集计算齐备，`partial` 不能显示为整栋楼总量。

范围覆盖审阅以独立的冻结清单为基准，绑定参与图纸版本、楼层/视图、专业、构件类别及空间范围，不能由识别器生成的候选列表反推范围。清单包括范围内源实例到候选的归属、未纳入候选的来源、已排除来源及理由、重复关系和解析缺口；批量排除须保存可展开的成员与依据。未知楼层/视图归属及无法定位的解析缺口不得静默排除。源图元归属仅辅助检查，不能用“每个图元都有归属”证明没有漏掉业务构件。

覆盖状态为 `unknown`、`incomplete` 或 `reviewed_complete`；独立的人工覆盖审阅须对照原图或可核验参考清单，记录证据、审阅范围与结论，遵循同一可信人工确认入口。候选全部确认不自动产生覆盖完成结论。只有覆盖为 `reviewed_complete`、构件与参数审阅通过、规则检查通过且不存在未决影响项，才允许声明冻结范围完成；覆盖未知或有缺口时仍可输出已知小计，但范围状态保持未完成。结果绑定覆盖审阅版本，图纸、范围、归属、排除或候选变化后使相关覆盖结论及完成声明失效，重新核验后才能恢复。

## 7. Web 审阅器范围

保留：二维图纸、图层、缩放/定位、框选、候选高亮、构件表、批量核对、范围覆盖审阅与未归属来源定位、参数来源、诊断定位、公式/扣减明细、成果查看、工程资料发送设置。

移除：项目首页和项目增删改、独立 AI 聊天、Codex 登录与账号配置、模型选择、宿主会话管理、通用 CAD 编辑入口。

打开链接即可进入指定图纸/审阅批次，展示当前版本及失效提示。批量确认前呈现范围与待确认内容。提交使用版本比较；图纸或候选发生变化后，旧页面拒绝写入并提示刷新。关闭后可从 Codex 继续或再次打开，同一任务不依赖浏览器 localStorage。

## 8. 实施顺序与验收

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| P0 工作目录内核 | 先抽共享模型输出过滤与审计；冻结多图 schema；拆出领域层；目录绑定；本地导入；独立 CLI/MCP；单运行时；保留快照与任务 | 关闭 Web、不启动 App Server，在任意临时目录完成 DWG 导入→诊断→受控算量→导出；两个目录互不串数据；摘要策略下各模型输出路径均不泄露被限制的几何 |
| P1 插件与审阅闭环 | 插件清单、Skill；首个平台发行包及依赖检测；精简 Web；审阅批次；参数与确认适配；资料策略人工设置 | 在干净 macOS arm64 环境中，仅预装声明的依赖和目标 Codex，从发行包安装并完成真实 DWG 导入→CAD 解析→人工核对→几何 Worker 计算→导出；定位核对、恢复任务、旧审阅拒绝提交；不出现项目管理或第二套聊天 |
| P2 首批建筑算量 | 基于 P0 输入清单的多图业务编排；楼层/视图范围；独立覆盖审阅；柱/板/门窗；洞口和重复检查；依据报告 | 真实建筑样本逐构件对照参考清单；误识别、漏识别、数值误差与人工工作量分别记录；故意漏识别一个目标构件时，即使其余候选均确认也不得声明范围完成；覆盖未知或不足时输出部分结果 |
| P3 墙与规范量 | 墙线组装、交接与洞口；规范规则版本；跨视图关联 | 参考样本验证墙工程量、扣减与去重；每项量可反查来源和计算式 |
| P4 扩展分发与迁移 | 扩展平台依赖与 Worker 分发；旧数据复制迁移；性能及升级验证 | 新增平台分别通过干净环境安装；首个平台升级不覆盖资料；迁移后源哈希与成果依据一致；记录真实大图耗时和内存 |

P0 内部依赖顺序：

1. P0.1 抽取共享模型输出边界层，先保持现有 HTTP/MCP 行为，用既有链路与新调用路径做过滤、分页、嵌套结果和审计一致性回归。
2. P0.2 冻结并落地多图 schema、工作目录绑定和迁移基础。
3. P0.3 抽领域层、本地导入与 CLI，再接独立 MCP；所有模型输出复用 P0.1。
4. P0.4 落地独立运行时、锁与恢复，完成无 Web 闭环和并发故障验收。

P0 期间保留旧启动入口与 `host.ts`，新旧入口并行可用，共享输出边界层，但使用隔离的数据目录，不同时写同一数据库。新插件链路从开始就不启动 `host.ts`。P0 验收通过后将旧宿主标记为兼容入口；P1 发行包不包含旧聊天宿主。完成 P1 闭环及资料策略回归后，再移除旧默认入口和 `host.ts` 的运行依赖；旧数据复制迁移仍按 P4 单独验收，不能以切换入口代替数据迁移。

P0/P1 验收仅表示插件化完成；P2/P3 才逐步验收建筑业务能力。实现开始前以当前测试作为回归基线，保留解析、单位、洞口、幂等、版本冲突和结果失效测试。新增验证聚焦工作目录隔离、MCP 独立启动、多图输入、审阅权限与并发；不沿用宿主聊天恢复作为新主链路验收项。

资料策略回归覆盖 `dwg_get`、构件列表、`job_get` 嵌套结果、分页及引用读取、错误输出与 CLI，检查默认摘要过滤、授权范围、策略变更审计及模型无法自行扩大权限。覆盖审阅回归包括漏识别、全部候选确认但覆盖未知、未归属来源、无依据排除、解析缺口、人工补充构件及覆盖结论失效。P1 安装验证不得读取源码 checkout、开发机虚拟环境或未声明的全局工具；同时验证依赖缺失诊断和只读安装目录，MCP 握手或工具列表成功不能替代两个 Worker 的真实调用。

旧 `.data/projects/<id>/` 采用显式、可重复执行的复制迁移到指定工作目录；迁移前备份，不原地删除旧数据。图纸、快照、构件与成果优先迁移；旧会话作为历史记录可选保留，不恢复为新 Codex 会话。旧运行入口待新闭环通过再移除。

## 9. 首版范围及待定参数

首版按“本地 Codex 插件 + 二维建筑图 + 柱/板/门窗 + 人工核对 + 可追溯工程量”推进。默认沿用当前已验证的 macOS arm64 技术栈作为首个平台，其他平台通过单独安装验证后列入支持矩阵。

后续需结合实际任务确定：目标 Codex 版本与分发渠道、适用工程量规范及地区版本、首批真实样本与人工参考清单、楼层与专业范围、性能和识别精度目标。以上不阻塞 P0，但正式建筑工程量验收前必须明确规则与参考答案，不能用“全图解析成功”替代。
